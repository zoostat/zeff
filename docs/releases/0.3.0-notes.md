# Zeff 0.3.0 — Distributions

Released 22 October 2026. The third release of the Zeff engine is its probability toolkit: the
special functions of statistics in pure Rust; twelve distribution families as values, each with
`pdf`, `cdf` (both tails computed directly), `quantile` and `draw`, and truncation and finite
mixtures built on them; random streams that give the same draws on every machine and in the
browser, with `seed`; `correlation` and `covariance` with the p-values of R's `cor.test`;
`zeff selftest`; and 26 functions, each with its complete help page. The sample project
`samples/simulation/` is the release's analysis: a seeded simulation with its p-values end to end.

## What shipped

**Commands.** `zeff selftest` runs the 81 conformance cases compiled into the binary against the
published report and says whether this installation is conformant (exit code 0) or names the
cases that differ (exit code 1); `--format json` gives the cases as records. The identity jobs of
CI run it on every target.

**Language.** The `Distribution` type (Language Reference, section 4) and the `dist.` namespace:
`dist.normal(mean: 100, sd: 15)` is a value that prints as its call with the defaults filled in,
can be bound to a name and used inside `add`, and has the methods `pdf`, `cdf` (with `upper:`),
`quantile` and `draw`, which apply to a value or, row by row, to a column. `dist`, `power` and
`spec` are reserved names (Z0105). A parameter outside its domain, or a probability outside
[0, 1], is Z0413, with its explained page.

**Randomness.** Philox4x32-10, checked against the published test vectors, keyed by the seed, the
statement's ordinal, the loop pass and the call within the statement; 53-bit uniforms; every draw
by inverse CDF (a mixture spends two uniforms), so a run is a pure function of its seed on every
target. `seed(n)` sets the run's seed once, before any draw (Z0111 when it comes later or twice);
without it the engine chooses a seed and notes it, so that `seed(n)` repeats the run exactly;
`draw(n, seed:)` is a stream of its own wherever it is written. Draws from a discrete family are
Int columns, Float otherwise; `draw(1)` is a column of one value (question 3 of the checklist).

**The numeric kernel.** `zeff_numeric::special`: the gamma and beta functions, factorials and
binomial coefficients (exact while they fit), the error functions, the normal tails and quantile
(Wichura's AS 241), the regularised incomplete gamma and beta functions with both tails computed
directly and their inverses, and Loader's deviance for the discrete masses, all in pure Rust on
every target. The kernel is held to an exact reference in Python's `decimal` module at 70 digits
(599 values) within 1e-12 in the distribution class, and to R.

**Tables.** `correlation` and `covariance` print a square table with three decimals and
`N = 1,139` under the title; `p_values: true` adds a table headed `p-values`, and a table `N per
pair` follows under pairwise deletion when the Ns differ (question 2). A `Table` value may carry
further tables.

**Diagnostics.** 71 codes, two more than 0.2.0 (Z0413, Z0111), each with a snapshot of its
wording and an explained page behind `zeff help <code>`. Open decision #46 settled the four
provisional codes raised during 0.2.0 (Z0221, Z0222, Z0410, W0102), and section 11 of the Language
Reference now lists every code numbered while the engine was built. The specification freeze
(#40) ended with this release.

**Testing.** The R reference harness gained `special.R`, `distributions.R` (35 parameter sets and
four composites) and `association.R`, beside the exact `special.py`; the nightly job runs the
stochastic class (14 distributions, 50 seeds of 100,000 draws each); a fifth fuzz target feeds
extreme parameters and probabilities through the whole engine, and the fuzz job now fails on a
crash, which it could not before; the weekly job is a coverage job and mutation testing in shards.

## Functions by package

**core (tier 0), 38 of 71** (6 new).

- Special functions: `factorial`, `choose`, `gamma`, `log_gamma`, `beta`, on values and on columns
  row by row, with the warnings of section 4.1 (`NA` at a pole or a negative argument, `Inf`
  beyond the largest Float); each page names the logarithmic form that stays finite.
- Program: `seed`.

**stats (tier 1), 2 of 34** (new package).

- `correlation` — Pearson, Spearman (ties averaged) and Kendall tau-b; `missing: pairwise |
  listwise`; `p_values:` reproducing R's `cor.test` branch by branch, the exact distributions
  included (Spearman without ties up to n = 1,290, Kendall without ties below n = 50); a constant
  variable gives `NA` with W0205.
- `covariance`.

**dist (tier 1), 18 of 19** (new package).

- Families: `dist.normal`, `dist.lognormal`, `dist.uniform`, `dist.exponential`, `dist.t`,
  `dist.chi2`, `dist.f`, `dist.gamma`, `dist.beta`, `dist.binomial`, `dist.poisson`,
  `dist.negbinomial` (in both its forms).
- Constructions: `dist.truncated` (a closed interval, both tails direct, a draw from one uniform)
  and `dist.mixture` (`probs:` summing to one; the quantile by halving a bracket).
- Methods: `pdf`, `cdf` (`upper:` computed on its own side, so a tail of 1e-300 keeps its
  digits), `quantile`, `draw` (`seed:`).

## Breaking changes

Six names became functions of `core`, which a script cannot rebind (Z0105): `factorial`,
`choose`, `gamma`, `log_gamma`, `beta` and `seed`; and `dist`, `power` and `spec` are reserved.
A 0.2.0 script with `let beta = 0.5` or `let gamma = 2` is refused; the rewrite is to rename the
binding (`let beta_hat = 0.5`). `let correlation = …` and `let covariance = …` still run, with the
warning W0101 that they hide a function of `stats`. No printed result of a 0.2.0 script changes:
the 66 conformance cases of 0.2.0 kept their hashes through the release.

## Reference versions

- R 4.6.0 (base R only, no packages; pinned in `tests/reference/r/renv.lock`; run in CI through
  `r-lib/actions/setup-r`). Its scripts write the special-function, distribution and association
  references beside the maths, descriptive and frame ones of 0.2.0. The `truncdist` package cannot
  be installed under the project's rules, so the truncation reference is written from base R's
  own functions. The boundary of R's exact Spearman branch is n ≤ 1,290, not n < 1,290 as its
  documentation reads.
- Python 3.14.8: the `decimal` module at 70 digits for the exact special-function reference
  (599 values) and the exactly rounded maths reference; the `statistics` module for the
  descriptive reducers; the dataset generator.
- Node 22 (v22.23.3 in CI) for the WebAssembly target. No Stata output at this release.

## Validation

- 626 tests pass on every push (unit, reference, edge-case, property, snapshot, help, script,
  stochastic); format, clippy with warnings denied, the tier rule and the message rule enforced
  (every code with a snapshot and an explained page).
- Bit-identity: the conformance report (81 cases: the 66 of 0.2.0, eight special-function
  series, two of the raw stream and its uniforms, two of draws, and the simulation sample's three)
  is identical on Linux x86-64 at the baseline and at the x86-64-v3 instruction level, Linux
  ARM64, macOS ARM64 and WebAssembly (SIMD128) under Node 22. No run of the release showed a
  cross-target difference. `zeff selftest` reports 81 of 81 on the development machine.
- The three sample projects (`first_engine`, `data_cleaning`, `simulation`) run to their stored
  output byte for byte on every target.
- Agreement with R: every printed value of the 35 parameter sets and four composites of
  `distributions.R` (densities, both tails and quantiles on grids reaching the far tails) agrees
  with R at six digits; the 22 pairs of `association.R` agree with `cor.test` within 1e-12 in
  estimate and p-value; the kernel holds the exact decimal reference within 1e-12.
- Nightly (run 39715853858): every property test at 25 times its usual cases in release mode;
  the stochastic class, 14 distributions under 50 seeds of 100,000 draws each: every mean within
  five standard errors and the seeds' errors leaning no way (summed z-scores between −1.64 and
  +1.10 against a limit of 4.5), every variance within five per cent, the worst
  Kolmogorov–Smirnov distance 0.0060 against 0.0082, the same figures to the last digit on macOS
  and Linux. Fuzzing (run 39727701712): ten minutes per target, 1,520,598 inputs to the lexer,
  484,339 to the parser, 129,847 to the checker, 362,703 to the CSV reader and 11,691 to the
  distributions, no crash. The first fuzz runs of the release found and fixed three faults (a
  quantile search that never returned, a draw that took eight seconds, a header check in the CSV
  reader that compared every pair of names) and one in the job itself, which could not fail on a
  crash.
- The review of the engine changes before the tag found two wrong results at large parameters,
  both fixed: the discrete distribution functions floored their point with a fuzz relative to it
  (P(X ≤ 10⁹) was computed as P(X ≤ 10⁹ + 100), wrong by 2.5e-3), and the kernel's gamma series
  returned a partial sum past its limit of terms (now `NA`). Regression tests hold R's values at
  parameters from 10⁷ to 10¹².
- Coverage (run 39821456272, on the release's tests): 91.3% of the kernel's 5,520 lines
  (`zeff-numeric` 97.2%); 91.2% of the workspace's 21,958 lines.
- Mutation testing of `zeff-numeric` (the same run): 1,874 mutants, 1,756 caught, 98 survivors,
  10 timed out, 10 unviable. Every survivor has a verdict in `docs/decisions.md` (22 and
  23 October 2026): 82 are equivalent, each with its reason (boundaries between formulas that
  agree, guards against exact values no input reaches, early returns that short-cut a path to the
  same answer, scratch vectors sized generously, Newton's safeguards), and 16 were given kernel
  tests after the run, each confirmed caught by rerunning its mutants. The ten timeouts are nine
  loops or enumerations a mutant stops advancing, on which a test can only time out, and one slow
  mutant the kernel's own tests catch in seconds. An earlier four-shard run had reported 47
  survivors and 59 timeouts: its extra catches came from a flaky property (the inverses'
  round-trip test, which asked for more than the doubles near one can give) since repaired, and
  its extra timeouts from two dist tests that make over a million kernel calls, which the job now
  skips under mutation.
- Browser build: the compressed engine bundle is 1,151 kB (brotli; 1,578 kB gzip; 7,053 kB raw)
  against the 5 MB limit of risk R4, up from 1,101 kB at 0.2.0 with the special functions and
  distributions; cold start 140 ms against 1,000 ms.
- Build: a clean release build of the workspace takes 62 s on the development machine (60 s at
  0.2.0).

## Known issues

See `docs/known_issues.md`. New at this release: distribution functions with a parameter above
100,000 are accurate to about 1e-10, not the class's 1e-12; where the gamma series cannot converge
(shapes of about 10¹¹ and above, so the gamma, Poisson and chi-square functions there) the answer
is `NA`, and the incomplete beta function loses digits slowly near its centre (about 3e-10 at
10¹²); `correlation` with `method: kendall` costs time quadratic in the rows; draws are keyed by
position, so inserting a drawing statement or call changes the draws after it, as in R and Stata;
the truncation reference is written from base R's functions; the distribution fuzz target runs
slowly. Nothing on the 0.2.0 list is resolved at this release; the browser bundle's figures are
updated.
