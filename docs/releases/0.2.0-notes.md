# Zeff 0.2.0 — Data cleaning

Released 19 October 2026. The second release of the Zeff engine runs everyday data cleaning end to
end: expressions over values and over whole columns with the rules for `NA`, `NaN` and `Inf`; the
frame verbs from `head` to `sort`; 27 maths functions and constants, each a pure-Rust
implementation that gives the same bits on every machine; the descriptive reducers with `by:` and
`weights:`; `warn` and `error`; the console (`zeff repl`) and `zeff eval`; the command-line options
of section 2.1; the shipped datasets `wages` and `sleep` behind the `zeff:` data root; an R
reference harness beside the Python one; and 50 functions, each with its complete help page. The
sample project `samples/data_cleaning/` is the release's analysis: a German spreadsheet export
cleaned, derived, grouped and summarised.

## What shipped

**Commands and options.** `zeff repl [script]` opens the console, which keeps what is typed in
`.zeff/session.zeff` (`:undo`, `:vars`, `:save`, `:load`, `:help`, `:quit`; a line beginning with
`.` continues the previous statement); `zeff eval "<statement>"` runs one statement; outside a
project both use the scratch project in `~/.zeff/scratch`. `zeff help Z0101` explains a diagnostic
code. Options: `-p/--project`, `--format text|json` (JSON records of every diagnostic for an
editor), `--color auto|always|never` (NO_COLOR honoured), `--ascii`, `--width <n>`, `-q/--quiet`,
`-v/--verbose`.

**Language.** Operators with the precedence of section 3.3 over values and over columns (a scalar
function applied to a column works row by row, its warnings counted once); ranges `2..6`, mappings
`[k => v]`, records and indexing; the truth table of `NA`; Int overflow refused; `-0.0` and `0.0`
one value in grouping and sorting. Inside a frame method's argument a bare name is the frame's
variable first and a binding second, resolved when the statement runs, with a warning when it is
both; variable ranges `x1..x9`. Definitions in `add` and `update` are evaluated left to right and
may use a reducer, computed group by group under `by:`.

**Columns.** The column-type interface of section 4.3: the nine metadata keys (labels, units,
value labels, categories, panel declaration and the rest) carried as Arrow extension metadata, the
opaque kinds, the reserved type names (Z0105), and Arrow IPC round trips. Labelled values print
their labels; `describe` marks them `Int (lab)`.

**Import.** The options of section 6.1 for delimited text are complete: `quote:`, `decimal:`,
`thousands:` and `encoding:` (any encoding of the WHATWG list, through `encoding_rs`) join `delim:`,
`header:`, `skip:`, `na_values:`, `types:` and `names:`. Every imported file is hashed with BLAKE3.

**Datasets.** `dataset(wages)` and `dataset(sleep)` load the shipped datasets with their labels,
value labels, categories and panel declaration; `datasets()` lists them; `import("zeff:wages.csv")`
reads the same files through the `zeff:` root. `wages` is synthetic (18,412 rows on 3,911 workers,
2010 to 2021, generated from documented parameters by `packages/tier1/datasets/generate/wages.py`,
seed 20261019, CC0-1.0); `sleep` is Student's 1908 data (public domain). Both ship as CSV and Arrow
IPC, reproduced by their scripts on every CI run and recorded in `data/CHECKSUMS`.

**Diagnostics.** 69 codes are raised, each with a snapshot of its wording and an explained page
behind `zeff help <code>`: nine more than 0.1.0 (expressions, overflow, the options that exclude
each other, the console and the data roots). A warning printed under a result shows no code, as
section 10.2 prints it (open decision #45); `--format json` and the explained pages carry it.

**Testing.** The R reference harness (`tests/reference/r/`, base R 4.6.0) runs in CI beside the
Python one; the four-target identity report has 66 cases; four fuzz targets run nightly; the
dataset scripts are re-run on every build.

## Functions by package

**core (tier 0), 32 of 71** (31 new).

- Maths: `abs`, `sign`, `sqrt`, `exp`, `log` (with `base:`), `log2`, `log10`, `log1p`, `expm1`,
  `round` (`digits:`, `sig:`, `mode: even | away`), `floor`, `ceil`, `truncate`, `min`, `max`
  (row by row), `div`, `mod` (floored), `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`,
  `is_finite`, and the constants `PI` and `E`. Each scalar function applies to a column row by
  row; the warnings of section 4.1 (a negative square root, the logarithm of zero or a negative
  number) are counted once per statement.
- Missing values: `is_missing`, `coalesce` (types joined; Z0214 when they cannot be).
- Program: `warn` (a codeless warning, the script continues), `error` (Z0001, the script stops).

**data (tier 1), 26 of 65** (17 new).

- Frames: `head`, `tail`, `where` (rows where the condition is `NA` are dropped and counted, the
  note naming the variable to inspect), `select`, `drop`, `rename`, `add` (definitions left to
  right; a replaced variable noted), `update` (`where:`; the variable keeps its type and metadata),
  `sort` (stable; `NA` last in both directions; text by code point).
- Reducers and summaries: `variance`, `median`, `quantile` (the nine Hyndman and Fan definitions,
  agreeing with R to the bit), `min`, `max`, `sum`, `n`, `n_distinct`; and on every statistic, on
  `summary` and on `describe`, `by:` giving a table in key order, and `weights:` with
  `weight_type: frequency | analytic | sampling` under the formulas recorded in
  `docs/decisions.md` (19 October 2026, the reducers).

**datasets (tier 1), 2 of 2** (new package).

- `dataset` — a shipped dataset as a frame with its labels, categories and panel declaration.
- `datasets` — the table of shipped datasets: name, rows and columns, kind, licence, source, size.

## Breaking changes

None for scripts written for 0.1.0. One correction of the specification changes the console only:
a later `let` of the same name shadows the earlier one, as section 3.1 of the Language Reference
says, instead of being refused (`docs/spec_changes.md`, 18 October 2026).

## Reference versions

- R 4.6.0 (base R only, no packages; pinned in `tests/reference/r/renv.lock`; run in CI through
  `r-lib/actions/setup-r`). Its scripts write the maths, descriptive and frame references; the
  maths and descriptive files are compared within 1e-13 and 1e-12, the frames byte for byte,
  because R's elementary functions and `%%` on Floats differ between platforms.
- Python 3.14.8: the `statistics` module (exact rational arithmetic) for the descriptive reducers,
  the `decimal` module for the exactly rounded maths reference and the dataset generator, the `csv`
  module for the splitting of CSV files.
- Node 22 for the WebAssembly target. No Stata output at this release.

## Validation

- 567 tests pass on every push (unit, reference, edge-case, property, snapshot, help, script);
  format, clippy with warnings denied, the tier rule and the message rule enforced (every code with
  a snapshot and an explained page).
- Bit-identity: the conformance report (66 cases: 36 reducer cases, four canaries, 17 maths
  series, the milestone script and the two sample projects) is identical on Linux x86-64 at the
  baseline and at the x86-64-v3 instruction level, Linux ARM64, macOS ARM64 and WebAssembly
  (SIMD128) under Node 22. No run of the release showed a cross-target difference.
- The sample projects `samples/first_engine/` and `samples/data_cleaning/` run to their stored
  output byte for byte on every target.
- Nightly: all tests in release mode with every property test at 25 times its usual cases.
  Fuzzing: about three million inputs to the lexer, the parser, the checker and the CSV reader in
  the first ten-minute run of each target, no crash.
- Coverage: 90.0% of the kernel's 4,507 lines; 90.5% of the workspace's 18,756 lines. Mutation
  testing of `zeff-numeric`: 502 mutants, 500 caught, 1 unviable, none timed out, 1 survivor (a
  guard unreachable through `round`, since covered by a unit test).
- Browser build: the compressed engine bundle is 1.10 MB (brotli; 1.50 MB gzip; 6.82 MB raw)
  against the 5 MB limit of risk R4, up from 355 kB at 0.1.0 because the two datasets are
  embedded; cold start 132 ms against 1,000 ms.
- Build: a clean release build of the workspace takes 60 s on the development machine.

## Known issues

See `docs/known_issues.md`; as of this release: printed widths count characters (East Asian wide
characters misalign a table); `summary` and the grouped tables print fixed three-decimal
statistics, and `quantile` with a list prints one value per line; CSV dates only in ISO form or
with a declared format; labels, value labels and categories come only from the shipped datasets
until `label`, `category` and `recode` arrive; a line beginning with `-` is refused by the
grammar; `import` reads delimited text only, and the `zeff:` root holds CSV and Arrow IPC, with
Parquet at 0.11.0; `:undo` re-runs the session; the browser bundle grew to 1.1 MB; projects pin the
exact engine version and there is no launcher yet. Resolved since 0.1.0: `by:` on the statistics;
`thousands:`, `encoding:`, `quote:` and `decimal:` on `import`.
