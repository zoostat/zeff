## Rulings taken from the specification (engineering; each recorded in `docs/decisions.md` in the step that needs it)

- **`identify` is the first package of tier 3**, `packages/tier3/identify`, with the tier check extended to it. `Dag` is declared in `core` (section 8.1, rule 4) and implemented there. Its algorithms are exact and work on integers alone: ancestors and descendants, the expansion of `a <-> b` into a latent common cause, selected nodes conditioned in every criterion, d-separation on the moral ancestral graph, the generalized adjustment criterion as dagitty implements it, and every list in a canonical order (by size, then by name), so that the output is the same on every target by construction. `fit.check` and `iv.exclusion_check` read a fit through the result interface (its outcome, its regressors' variables, its instruments), so `identify` names no model package.
- **The `dag { }` block.** The lexer's graph mode, the parser and the formatter have held the block since the parser of 0.1.0, and the checker refuses it (Z0304); this release lowers it to a value. A directed cycle is an error that names the cycle, under a provisional code with its row in section 11's table; `--` is kept for drawing and refuses the criteria, as section 7.3 says; W0510 and W0511 are used as given.
- **`measure` is a new package of tier 2** with `reliability` alone. The catalogue plans it in Zeff; it is written in Zeff if the language of this release expresses it and in Rust otherwise, the layer corrected and logged as before.
- **The layout engine lives in `plot`** (catalogue row 501), stage 1 of #190 if taken as recommended: layers by network simplex, crossings reduced by the median rule in a fixed number of sweeps, coordinates by Brandes and Köpf, straight and spline edges, label boxes; a fixed order of every loop and no outside crate, so that the same graph is always laid out the same way and the bytes of its figure agree on the four targets. No Graphviz or other layout program is linked.
- **`publish` is a new package of tier 1.** #141 places it after `plot`; section 8.5 calls `datasets` the last of tier 1, and `cite(wages)` reads a dataset's citation. The order of the three is settled at step 26 from what each calls, and the sentence of section 8.5 corrected if it must be, logged. `report()` moves with no change to anything it prints.
- **References as data.** The references of the help pages become structured entries, one file per package, from which each page's References part is generated and `cite` reads; an option's own references are declared beside the function's help. No bibliography crate is added: the three formats are written by the engine.
- **The validation record.** One record, generated from the catalogue, the reference files and the conformance suite, with a test that fails when a function of status implemented has no entry, fewer than two datasets, or no edge-case result; the report of question 7 and each page's Accuracy part (section 9.1) are printed from it. A reference the release could not run (Stata) is printed as not run, never left blank.
- **The routine (R7).** No test is dropped and the standing rule (format, lint, every test, before every commit) is kept. Step 2 measures where the forty minutes go and removes what is not testing. (Corrected at step 2, 27 November 2026: the planning took the cost to be the linking of some 350 test programs. Measured, building and linking take a minute and a half and the tests ran for 27 minutes as unoptimised code; the remedy is light optimisation of development and test builds, and the programs are not gathered.)
- **Fonts (#222).** Static TrueType faces under the Open Font License, unchanged, each recorded with its licence in `docs/decisions.md` and in `NOTICE`; the bundle is measured against R4 at the step.
- **Codes.** Codes the text gives are used as given; conditions it describes without a number receive provisional codes with their rows in section 11's table, logged.
- **Catalogue and counts.** New rows for `cite` and for whatever question 2 brings (`instruments`; `residual_plot`, `influence_plot` and `calibration` moved from their later releases); `report`'s package; each row marked implemented in the step that ships it; the counts of sections 8.2, 9.2 and 14 follow at each step and are logged.
- **Help pages.** Every page of this release is written to the help contract of 0.8.0, in the project's own words, every example on the shipped datasets.
- **Not pulled forward.** Omega (1.12); `render` and the documents (after 1.0); `zeff cite` (0.11.0); cycles, orthogonal routing, groups and ports in the layout (1.2); the drawing of `sample_flow` (1.2); `help()` and `version()` and help built from `///` (0.11.0); replication packages and `zeff verify` (0.11.0); the bridges to R and Python; the website (1.0.0).
