# Release 0.3.0 — Distributions

The row of section 14 of the Engine and Project Specification: 26 functions (the special functions `factorial`, `choose`, `gamma`, `log_gamma`, `beta`; `correlation` and `covariance`; twelve distributions with `pdf`, `cdf`, `quantile` and `draw`, plus `dist.truncated` and `dist.mixture`; `seed`), on these engine pieces: the incomplete beta and gamma functions, inverse CDFs and accurate tails; Philox counter-based random streams; the determinism contract in full, proved by the four-target CI that has run since 0.1.0; `zeff selftest`. The analysis it runs end to end: simulation and p-values.

How to read this file: as `docs/releases/0.2.0.md`. Each step is small enough to finish and commit in one session; **[engine]** marks a hard engine piece, **[function]** a catalogued function on machinery that exists. The specification freeze (open decision #40) is in force until this release closes: corrections are logged in `docs/spec_changes.md`; other design questions become open decisions.

## Questions only the owner can answer

1. **How a distribution prints.** Section 3.8 of the Language Reference gives printing rules for every value except `Distribution`; `dist.t(df: 24)` typed on its own must print something. Recommendation: one line in the form of the call that made it, with the parameters named and the defaults filled in, `t distribution · df: 24` and `normal distribution · mean: 0, sd: 1`; a truncated or mixed distribution adds its bounds or its components. Needed at step 3.
2. **The correlation and covariance tables.** The catalogue says "correlation matrix, N per pair, optional p-values" and section 4 says matrix results are Tables, but no section shows the layout. Recommendation: a square table with the variables as both rows and columns, correlations to three decimals; `p_values: true` adds a second table of the same shape headed `p-values`; the N per pair is a third table only when `missing: pairwise` and the Ns differ, otherwise one line `N = 1,139` under the title. Needed at step 11.
3. **Draws from discrete distributions.** `draw(n)` from a binomial, Poisson or negative binomial distribution gives whole numbers. Recommendation: a `Column<Int>` for those three (so `wages.add(y = dist.poisson(lambda: 2).draw(n))` makes an Int variable, as R's `rpois` gives integers), a `Column<Float>` for the others, and `draw(1)` still a column of one value, never a scalar, so every draw prints and binds the same way. Needed at step 7.
4. **Open decision #46, due at this release.** The four provisional codes raised during 0.2.0 (Z0221 an operator applied to types it does not take; Z0222 a mapping key written twice; Z0410 two options that exclude each other; W0102 a name that is both a variable and a binding). Recommendation: accept all four; since the freeze also ends at this release, the numbers are added to section 11 of the Language Reference at the close, with those of #41 to #44, and the change logged. Needed at step 15.

## Rulings taken from the specification (engineering; each recorded in `docs/decisions.md` in the step that needs it)

- Every special function and every distribution function is written in Rust inside the numeric kernel (`zeff-numeric`), on the pure-Rust elementary functions of 0.2.0, with fixed algorithms and no third-party special-function crate on a result-bearing path (section 8.3, point 3). Tails are computed directly, never as one minus the CDF (section 13). The reference is R 4.6.0's `d*`, `p*`, `q*` functions and, for the hard tails, values computed in exact arithmetic by Python's `mpmath` in the reference scripts (tooling only, never linked); the class is "distribution functions, within 1e-12 relative".
- The random stream is Philox4x32-10 exactly as section 8.3, point 3 writes it: a draw is a function of (seed, the ordinal of the drawing statement within the run, loop pass, draw number); a uniform Float takes 53 bits from two 32-bit outputs; every distribution draws by inverse CDF from the uniform stream, `dist.mixture` with two uniforms. The seed given to `seed(n)` is the script's; `draw(n, seed:)` uses its own; when neither is given a seed comes from the operating system once per run and is printed as a note, as the catalogue's row 63 says. The stream is checked for bit identity across the four targets in the conformance report, and its first values are fixed against the published Philox test vectors.
- `dist.` is a namespace, not a value (section 3.7, "Namespaces"): the checker resolves `dist.normal(...)` to the catalogued function without a binding `dist` existing; a script that binds `dist` itself is refused with Z0105 like any `core` name. `Distribution` is a value type declared in `core` (section 8.1, rule 4) and implemented in `dist`; `pdf`, `cdf`, `quantile` and `draw` are methods on it (the catalogue's kind "result method"), the first methods on a value that is not a frame, so the checker's method dispatch is widened once and later result types reuse it.
- `pdf` on a discrete distribution is the probability mass; `quantile(p)` on a discrete distribution is the smallest value whose cumulative probability reaches `p`, as R defines it; a parameter outside its domain or a probability outside [0, 1] is Z0413 (section 4 of the Language Reference); `seed` called twice, or after a draw, is Z0111 (row 63). `cdf(x, upper: true)` computes the upper tail directly.
- `stats` is a new tier-1 package after `dist` in tier order (section 8.2: `dist` 4, `stats` 6), so `correlation` may use the t distribution of `dist` for its p-values; Kendall is tau-b; `missing: pairwise` is the default, as the catalogue says. `correlation` and `covariance` return Tables.
- `zeff selftest` runs the conformance cases compiled into the binary against the published report of the release (`crates/zeff-conformance/expected.txt`, compiled in at build time) and prints the line of section 2.1, `conformant: N of N cases match the published results of Zeff 0.3.0 on this machine (<target>)`, or names the cases that differ and exits with code 1. `zeff doctor`, the launcher and the unofficial-build mark belong to 0.9.0 and are not pulled forward.
- `dist.tukey` (the studentized range) is a 0.7.0 function and is not pulled forward; nor are `t_test` and the other tests of `stats`, `sample`, `assert`, `attempt` or `for` loops. Draws inside a loop therefore do not arise at this release; the "loop pass" component of the stream is zero and the design leaves it room.
- New tests of the handbook used from this release: the stochastic class (Zeff reproduces itself exactly with the same seed; against R, agreement within Monte Carlo error over 50 seeds, nightly) and the first truth-recovery tests (the sample moments of 1,000,000 draws against the distribution's moments).
