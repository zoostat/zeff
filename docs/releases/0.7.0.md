# Release 0.7.0 — Tests, plots and the language server

The row of section 14 of the Engine and Project Specification: 62 functions (`note` and `name_of` in `core`, added by open decision #70 at step 3.1; `tabulate` in `data`; in `stats` the nine tests `t_test`, `wilcoxon_test`, `kruskal_test`, `chi2_test`, `fisher_test`, `proportion_test`, `shapiro_test`, `ks_test` and `anova` with factorial tables, with `posthoc` and `p_adjust`; `dist.tukey`; the plot grammar and its shorthands, 35 functions, section 7.6 of the Language Reference; and the 12 remaining functions of `text`), on these engine pieces: the language server (completion, signature help, hover, live diagnostics), the tree-sitter grammar, `zeff fmt` and `zeff test`, ready for Zemp's prototype; the layered-grammar plot renderer with the Okabe–Ito and viridis scales, redraw to fit and journal sizes; the exact Wilcoxon distribution; the engine worker with progress, cancellation and the memory budget; `zeff completions`. What it unlocks: exploratory analysis, and the start of Zemp's interface. After it 245 of the 259 functions of 1.0 are implemented, before the names the owner's decisions of 6 November add: `note`, `name_of`, `map`, `filter` and `reduce` in `core` and `design` in `results` (open decisions #70, #79 and #71), whose catalogue rows and counts are added in the steps that build them (3, 3b and 30).

How to read this file: as `docs/releases/0.6.0.md`. Each step is small enough to finish and commit in one session; **[engine]** marks a hard engine piece, **[function]** a catalogued function on machinery that exists. A change to the normative text is made only to correct an error found while coding and is logged in `docs/spec_changes.md` with its date, section and reason; a design question the text does not settle becomes an open decision with a deadline release. The lessons of the earlier closes stand: every reference file carries inputs from 1e7 to 1e12 beside its working grid; every property test is written to what doubles can give; every new message comes from the diagnostics-as-data path with a snapshot and an explained page; a step that turns out too large is split here, not pushed through. This is the largest release of the plan, by count (60 functions) and by engine work (three of the seven hard pieces of 1.0 meet in it: the special distributions of the tests, the plot renderer and the language server), so the checklist is long and its steps are kept narrow.

## Questions only the owner can answer

1. **The open decisions due at this release.** Recommendation, each as the register recommends: #68, #69, #70 and #79 (the pieces a Zeff-written built-in lacks: a parameter of several types, the enclosing frame, `note` with `code:` and `name_of`, and `map` over a list), adopted and built in step 3, the functions that waited for them rewritten in Zeff in step 4; #71 (`design()` on a fit), adopted and built with the result plots (step 30); #76 option A (the full call chain of an error through module functions at this release; the inspector and "run to here" stay with Zemp's alpha); #77 option A (completion from the schema pass at this release; extract function at 1.1); #83 option A (the sentence of section 3.7 on bare words corrected, no change to the engine). #24 (the Zemp interface framework) cannot be decided before its two-week trial, which has not been run: the trial is run in a Zemp session during this release, outside this checklist and this repository, and the decision is taken before the close. #73's trial of the typesetting engine, planned beside the plot renderer, is run as a tool-only step once the SVG writer exists (step 22b), with nothing linked into the engine; its decision stays due at 0.8.0.
2. **`each(...)` (#80): with the tests or after them.** This release is already the largest of the plan. Recommendation: option B, the rule adopted and the word kept, the building left to the first later release with room; the tests then ship in their one-variable forms, and the two statistical choices of #80 (whether the adjusted p-value prints by default, and whether each test uses its own complete rows) wait until it is built.
3. **The R reference library.** The pinned library holds base R 4.6.0 with `sandwich`, `wooldridge` and `fixest`. Base R gives every test of this release except two. Recommendation: add `car` (the factorial tables of `anova`, types 2 and 3, are defined by the catalogue as `car::Anova`) and `nortest` (the Lilliefors correction of `ks_test`); compute Hedges' g and Cohen's d by their formulas in base R instead of adding `effectsize`; check `dist.tukey` against a 70-digit quadrature written in Python, since R's `ptukey` is itself accurate to about eight digits and the class asks for 1e-12.
4. **Definitions the catalogue leaves open, each recommended "as R does".** (a) `wilcoxon_test`: exact p-values when n is below 50 and there are no ties (for the two-group form, both groups below 50), otherwise the normal approximation with the continuity correction; `exact:` overrides. (b) `shapiro_test`: Royston's 1995 algorithm, as R and Stata. (c) `ks_test`: the exact distribution below 100 observations without ties, the asymptotic one otherwise; `estimated: true` only against the normal distribution, by the Dallal–Wilkinson approximation as `nortest`, and refused for any other distribution with a message saying so. (d) `fisher_test`: a 2 × 2 table gives the conditional estimate of the odds ratio with its interval; a larger table gives the p-value alone, and a table too large to enumerate is refused with `chi2_test` suggested. (e) factorial `anova`: partial eta squared beside each term, eta squared for the one-way form. (f) `posthoc` after Welch's ANOVA, the default: `tukey` is Tukey's HSD on the pooled variance, as R's `TukeyHSD`, with a note that the ANOVA did not assume equal variances; `bonferroni` and `holm` use pairwise Welch tests then and pooled tests after `equal_var: true`; the Games–Howell comparison becomes a new open decision instead of an unlisted option. (11 November 2026, step 19: the rule covers the one-way form; what `posthoc` compares after the factorial form is open decision #104 and step 19b.)
5. **The printed forms.** Recommendation: every test prints in the form the help examples give for `t_test` (the estimates, the difference or statistic with its confidence interval where one exists, the degrees of freedom, the p-value, an effect size, N and the rows dropped); `tabulate` prints counts with a percentage column, `NA` as its own row and a total row, the two-way form with the percentage chosen by `percent:` under each count. Each form is shown to you as a snapshot in the step that ships it, before the commit.
6. **The look of a plot.** Section 7.6 fixes the defaults (white background, major gridlines only, Okabe–Ito and viridis, text in points). What it cannot fix is taste: tick lengths, line widths, the spacing of a legend. Recommendation: the journal theme is drawn first on six sample figures (step 22), you read them by eye and say what to change, and the theme is frozen from that step.
7. **The fonts' licence.** Section 7.6 embeds IBM Plex Sans and Mono, which are under the SIL Open Font License; the standing list of licences (MIT, Apache-2.0, BSD, ISC, Zlib, Unicode) does not name it. Recommendation: allow the Open Font License for embedded fonts only, recorded in `docs/decisions.md`.
8. **Language-server features no row of section 14 places.** Section 12 says 1.0 ships formatting through the server, folding, snippets and the statement ranges behind "Run", and the row of 0.7.0 names four features only. Recommendation: formatting through the server at this release, since it is `zeff fmt`; the other three recorded as a new open decision, recommended for 0.8.0 with Zemp's alpha.

## Rulings taken from the specification (engineering; each recorded in `docs/decisions.md` in the step that needs it)

- `stats` and `dist` exist; `plot` is a new crate (`packages/tier1/plot`, tier 1, order 10) registered with the engine and the tier check; `text` gains its twelve functions in the existing crate. The renderer lives in `plot`; the scene format is a versioned JSON description of marks, scales and layout (section 8.3, point 5), and the SVG, PDF and PNG writers read the scene alone, never the plot value.
- Regular expressions follow Rust's `regex` crate (section 3.8), pinned exactly, with its licence recorded; it is the first third-party crate on a result-bearing text path, so its matching is checked identical on the four targets and its cost to the browser bundle is measured at the step. Case mapping uses a table generated from the Unicode data files (Unicode licence), not the platform's.
- The test statistics are computed by the engine's own kernels and distribution functions; p-values come from the tail computed directly. The exact Wilcoxon distributions (signed-rank and rank-sum) are counted in integers and are exact; the studentized range is of the distribution class (1e-12 relative), the Kolmogorov and Shapiro–Wilk p-values of the closed-form class (1e-6).
- Conditions the specification describes without a number receive provisional codes, the next free number of their family, each with its row in section 11's table, its explained page and its entry in `docs/spec_changes.md`. Codes the text already gives are used as given: Z0411 (sampling weights in a test), Z0412 (a group with one level or more than two), Z0317 (a pragma with an unknown code or no reason), Z0704 (the memory budget), Z0705 (cancellation), Z0716 (an export path naming no format).
- Fonts are embedded and never the system's (section 7.6); text is measured from the embedded fonts' own tables, so a figure's layout is the same on every machine. Text in non-Latin scripts needs the Noto subsets "fetched on first use and cached like a dataset", and the fetch store arrives at 0.11.0: until then a label with a character outside the embedded fonts is drawn with a placeholder and a warning naming the characters; the step that builds text reads section 8.5 and records this.
- The SVG and PDF bytes of the sample figures join the cross-target identity job (testing handbook, section 1). PNG is written by a pure-Rust rasteriser; whether its bytes are held identical or only its scene is decided at step 22b from what the rasteriser gives, and recorded.
- `zeff fmt` has no style settings ("no options", section 2); `zeff fmt --check`, which the testing handbook's routine names, changes nothing and exits 1 when a file would change. If the two texts are judged to disagree, the engine volume's line is corrected and logged.
- `zeff test` runs every `assert` of the project's scripts and every `/// >` example of its functions (section 5.3), prints one line per failure with what was expected and what was printed, exits 1 on a failure, and takes `--format json`. It also runs the engine's own help-page examples in CI, which resolves two entries of the known-issues list.
- The language server speaks the Language Server Protocol over standard input and output (`zeff lsp`). It reuses the checker, the registry and the cached schemas; it never runs a model. The library is chosen at the step between `tower-lsp`, which section 15 names "to confirm", and a smaller synchronous one, by licence, size and whether it builds for the browser, where Zemp calls the same functions without the protocol.
- The engine worker is a thread natively and a Web Worker in the browser; progress and cancellation are checked between steps; the memory budget follows section 8.3, point 7 (the estimate is a step's peak; Z0704 before the step starts). The browser path's benchmark joins the suite (testing handbook, section 6).
- The tree-sitter grammar lives in `editors/tree-sitter-zeff`, outside the workspace and linked into nothing; its corpus is the sample scripts and the conformance scripts, each of which must parse without an error node and agree with the engine's parser on statement boundaries.
- `zeff completions` covers commands, flags, function names and diagnostic codes at this release; engine versions join with the engine store at 0.9.0.
- Not pulled forward: `smooth`, `violin`, `aggregate`, `arrange` and `computed` (1.2); `segment`, `rect`, `arrow` and `path` marks, maps (after 1.0); `g.plot()` (0.10.0); quick fixes, navigation, rename and inlay hints (1.1); `zeff explain` and `zeff report-bug` (0.8.0); the run record, the result cache and the import cache (0.11.0); the launcher and `zeff doctor` (0.9.0); `each` unless question 2 says otherwise. By the ruling of 0.1.0 only working options are registered.
- The catalogue row of each function is marked implemented in the step that ships it, as since 0.2.0.
