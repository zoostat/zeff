# Release 0.5.0 — Language complete

The row of section 14 of the Engine and Project Specification: 32 functions (13 collection functions: `len`, `first`, `last`, `unique`, `sorted`, `reversed`, `any`, `all`, `append`, `keys`, `is_in`, `seq`, `vars`; `attempt` and `iterate`; 17 functions written in Zeff: `clamp`, `logit`, `inv_logit`, `fill_missing`, `n_missing`, `assert` in `core`, `drop_missing`, `standardize`, `center`, `between`, `row_mean`, `row_sum`, `iqr`, `mad`, `skewness`, `kurtosis` in `data`, and `vif` in `regress`; and `summary` rewritten in Zeff), on these engine and language pieces: `if`, `case`, `for`, `fn`, `use`, calling any function as a method, and the `Failed` type. What it unlocks: user-written functions. A 33rd function, `equal`, joined on 30 October 2026 when the owner took open decision #5 as recommended (question 1; catalogue row 529).

How to read this file: as `docs/releases/0.4.0.md`. Each step is small enough to finish and commit in one session; **[engine]** marks a hard engine piece, **[function]** a catalogued function on machinery that exists. A change to the normative text is an ordinary design decision, logged in `docs/spec_changes.md` with its date, section and reason; a design question the text does not settle becomes an open decision with a deadline release. The lessons of the earlier closes stand: every reference file carries inputs from 1e7 to 1e12 beside its working grid; every property test is written to what doubles can give; every new message comes from the diagnostics-as-data path with a snapshot and an explained page, which is the early warning of risk R5 and is first tested at this release. This release has no new estimator and no new kernel: its weight is in the checker and the interpreter, so most engine steps change `zeff-ir` and `zeff-engine`, and the functions written in Zeff are the proof that the language can carry its own library.

## Questions only the owner can answer

1. **The four open decisions due at this release.** By the register's status line, #4, #5, #13 and #17 are due by 0.5.0. Recommendation, each as the register recommends. #4 (variadic parameters), option B: no `...` in `fn`; a user function that takes several values takes a list, and variadics stay built-in only (`coalesce`, `min`, `max`, `print`, `vars`), so the item closes. #5 (structural equality), option A: `equal(a, b)` in `core`, using the identity relation of section 3.7 (`NA` equal to `NA`, `-0.0` to `0.0`, lists element by element, records field by field, mappings entry by entry), returning `Bool`; it makes `assert(equal(xs, [1, 2]), "...")` possible, which is how a project tests its own functions, and becomes the release's 33rd function with a catalogue row (`core`, Collections, 0.5.0, exact, Rust) added and logged. #13 (`iterate`): adopt, as the row of section 14 already counts it. #17 (panels at 0.6.0 before tests and plots at 0.7.0): keep the order. Needed at step 1. **Decided 30 October 2026: as recommended.**
2. **`iterate`'s `max:`.** The catalogue's usage gives `max: Int = 1000`; the recommendation of #13 says "keep `max:` required"; section 5.5 says a script always finishes "because `max:` is required to be finite". Recommendation: the catalogue's reading, a default of 1,000 passes, which is finite, with W0805 when the loop stops there without converging and the number of passes printed as a note; a user who wants to be made to think writes `max:` anyway, as section 5.5's example does. Needed at step 10. **Decided 30 October 2026: as recommended.**
3. **Printed forms the specification leaves open.** (a) A `Failed` value printed alone (section 3.8's table has no row for it): recommendation, one line, `failed · Z0801 at line 12: no row remains once rows with NA are dropped`, and in a list each failed item prints that line where its value would stand. (b) `vif`: a table titled `vif · m1` with the columns `term` and `vif`, three decimals, the intercept left out as `car::vif` leaves it out, a categorical regressor's columns each on their own row under their term names of section 7.2 (the generalised VIF of several columns is a later addition). (c) `drop_missing`'s message: a note in `where`'s words, `note: 228 rows with NA in educ or exper dropped (line 7)`, and `note: no row had NA in educ` when nothing is dropped. (d) `iqr`, `mad`, `skewness` and `kurtosis` print as `mean` prints, six significant digits, with the reducers' warning when values are skipped. Needed at steps 5, 18, 19 and 20. **Decided 30 October 2026: as recommended.**
4. **`any` and `all` with `NA`.** Two readings exist: the three-valued one of section 3.7's truth table, in which `any([false, NA])` is `NA` and `any([true, NA])` is `true`, `all([true, NA])` is `NA` and `all([false, NA])` is `false`, as R's `any` and `all` behave; or the reducers' rule of section 4.1, in which `NA` is skipped with a warning giving the count. Recommendation: the truth table, since `any` and `all` are `||` and `&&` over a list and should say what the operators say, and the reducers' rule is for statistics. Needed at step 13. **Decided 30 October 2026: as recommended.**
5. **`skewness` and `kurtosis` with too few values.** The adjusted G1 needs three values and the adjusted G2 four; the unadjusted g1 and g2 need two with a positive variance. Recommendation: `NA` with the reducers' warning W0205 ("one value only or an infinite value" extended to "too few values for the statistic"), as `sd` gives `NA` for one value, never an error, so a grouped summary over small groups still prints. Needed at step 20. **Decided 30 October 2026: as recommended.**

## Rulings taken from the specification (engineering; each recorded in `docs/decisions.md` in the step that needs it)

- Where the pieces live, by the tiers of section 8.1: `core` declares the `Failed` value and the function value (rule 4) and holds the collection functions in Rust (`core/src/collections.rs`) and its Zeff functions in `core/functions/`; `data` and `regress` hold theirs in `functions/` of their crates (section 9.1, "Files": one `.zeff` file per function, its page in the same file as `///` lines); the checker's control flow, functions, modules and types in `zeff-ir`; the interpreter's blocks, loops, call frames and `attempt` in `zeff-engine`; the loader of `functions/` in the engine's project module; the loader of built-in Zeff functions in the registry crate and the engine's registry module, since the page build check of section 9.1 lives there.
- Z0304 ("not available in this release") keeps only `model { }`, `dag { }` and `as` after this release; `if`, `case`, `for`, `[for ...]`, `break`, `continue`, `return`, `fn`, `use` and the spreads `..opts` in calls and `..r` in records all run. Spreads are in the grammar of section 3.4 and named by no later row, so a release called "Language complete" is where they arrive.
- The `layer` column of the catalogue is a plan, not a promise: each function it marks Zeff is written in Zeff where the language of 0.5.0 expresses it without a hidden door (no engine-only function, no construct outside the Language Reference). A function the language cannot yet express is written in Rust at its step, its `layer` corrected to Rust with the reason logged in `docs/spec_changes.md`, and the missing piece recorded as an open decision with a deadline release. The two at risk are known now: `summary` returns a `Table` and the catalogue has no table constructor before `aggregate` (0.6.0), and `vif` needs the fit's data or model matrix, which no result method exposes; `drop_missing`, `row_mean` and `row_sum` need a fold over a list of variables, which `iterate` gives. Whatever happens, every function of the row ships and prints the same bytes whichever language it is written in: `summary`'s digest in the benchmark suite and the identity series may not change.
- A built-in function written in Zeff is registered with a registry signature, which may list alternatives as the Rust built-ins' do (`x: Float | Column<Float>`), and its body is checked once for each alternative at engine start, so every form is proved before a script runs; a project function keeps the single types of the grammar (section 3.4, `type`). A scalar built-in in Zeff therefore applies to a column through the lifted operators and functions of its body in one pass over the data (section 3.7, "Columns and scalars"), never row by row through the interpreter, and a project function is not lifted (Z0218), as the text says.
- A Zeff built-in's "Warnings and notes" section is generated from the diagnostics declared by the functions its body calls (plus Z0001 where it calls `error` or `assert`), which is the help contract's "generated from the diagnostics the implementation declares" read for a body that is itself Zeff; the build check holds the page to the same completeness as a Markdown page (summary, description, every parameter, `returns:`, references for a statistical method, see also, one example that runs and prints what the page says).
- The random stream already keys each draw by (seed, statement ordinal, loop pass, draw number), as section 8.3 requires; step 3 feeds the pass and records it, and a draw inside a function takes the ordinal of the statement that called the function, since a function has no statements of its own in the run.
- The schema pass arrives at 0.6.0, so a `Var` parameter of a project function is checked against the frame it meets when the statement runs, with the codes of section 3.7; `zeff test` and `zeff fmt` arrive at 0.7.0, so the `/// >` examples of a module function are parsed and syntax-checked now (Z0319 requires one) and run from 0.7.0; the content-addressed cache arrives at 0.11.0, so nothing is cached, but the IR carries each function's hash from this release so that the cache of 8.3 point 4 can key on it.
- `zeff help <name>` run inside a project prints a project function's page when the project's `functions/` define the name (one source, four views: the page exists and the command exists), and `zeff check` fails a module whose function lacks the complete page (Z0319) or names a parameter it does not have (Z0320).
- Conditions the specification describes without a number receive provisional codes, the next free number of their family, each with its row in section 11's table of codes numbered while the engine was built and its entry in `docs/spec_changes.md`: unmatched rows of a `case` without `_` (W02xx); a method called on a binding that may hold a `Failed` value, unguarded (W02xx); a statement in a module file, which holds only `///`, `fn` and `use` lines (Z03xx); a `seq` with a zero step or a step of the wrong sign (Z04xx, as R's `seq` errors); a loop variable or parameter that is also a column of the frame is Z0106 as numbered. W0301 (an unreachable `case` arm) is raised for a literal `true` condition that is not the last arm, which is as far as a checker without constant folding reaches.
- `iterate`'s number of passes is printed as a note under the result, as the reducers' notes are, until the run record of 0.11.0 keeps it; W0805 when the loop stops at `max:`; `done(old, new)` is first called after the first step, so `step` always runs at least once.
- `logit(0)` and `logit(1)` are `-Inf` and `Inf` as the catalogue says, carrying `log(0)`'s warning W0204 as section 4.1 gives it, since the function is `log(p / (1 - p))`; `row_mean` and `row_sum` take Int and Float variables and refuse a Bool with the `to(x, Int)` hint of section 3.7, as arithmetic does; `between` is three-valued (`NA` where `x` is `NA`); `standardize` and `center` skip `NA` as `mean` and `sd` do and keep the warning.
- The reference harness stays R 4.6.0 with the pinned `renv.lock` (`sandwich`, `wooldridge`); no package is added: `vif` is checked against `1 / (1 − R²ⱼ)` from `lm` in base R, which is `car::vif` for single-column terms; `skewness` and `kurtosis` against the formulas of Joanes and Gill (1998) written out in base R, with the SPSS and Stata forms named in the page; the collection functions against base R's `length`, `nchar`, `unique`, `sort`, `rev`, `%in%`, `names`, `any`, `all` and `seq`, with each place R's `NA` handling differs recorded in the page. Every new reference file carries inputs from 1e7 to 1e12 beside its working grid.
- Mutation testing stays on estimator and variance code, as the handbook says; the weekly coverage report adds `zeff-ir` and `zeff-engine`, whose new code this release is mostly made of, and the nightly fuzz target for the parser and checker is extended to functions, loops and modules.
- Not pulled forward: `fe:`, `aggregate`, `data.append`, `panel` and the schema pass (0.6.0); `zeff test`, `zeff fmt`, the language server and the plot grammar (0.7.0); `logistic` and `probit`, which the specification's loop examples use (0.9.0; the samples use `reg`); the result cache and run records (0.11.0); `se: bootstrap`, `on_fail:`, `max_fail:` and parallel passes (1.1); closures (after 1.0); `model { }`, `dag { }` and `as` (their own releases). By the ruling of 0.1.0 only working options are registered.
- The catalogue row of each function is marked implemented in the step that ships it, as since 0.2.0.
