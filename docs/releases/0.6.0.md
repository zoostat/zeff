# Release 0.6.0 — Panels

The row of section 14 of the Engine and Project Specification: 36 functions (the `time` package, 14: `date`, `datetime`, `today`, `now`, `year`, `month`, `day`, `weekday`, `quarter`, `week`, `add_days`, `add_months`, `days_between`, `months_between`; the first function of `text`, `format`; in `data`, the frame methods `distinct`, `duplicates`, `sample`, `merge`, `append`, `to_long`, `to_wide`, `aggregate`, `panel`, `save` and the column functions `lag`, `lead`, `diff`, `running_sum`, `running_product`, `rank`, `quantile_group`, `bin`, `winsorize`, `fill_forward`; and `event` in `regress`), on these engine pieces: grouped computation; `fe:` demeaning in `reg`; date types; shared Arrow columns and selection vectors; the schema pass behind `zeff check`; data roots in `zeff.toml`. What it unlocks: panel research. A 37th function, `table`, joined on 1 November 2026 when the owner took open decision #72 as recommended (question 1; catalogue row 530).

How to read this file: as `docs/releases/0.5.0.md`. Each step is small enough to finish and commit in one session; **[engine]** marks a hard engine piece, **[function]** a catalogued function on machinery that exists. A change to the normative text is an ordinary design decision, logged in `docs/spec_changes.md` with its date, section and reason; a design question the text does not settle becomes an open decision with a deadline release. The lessons of the earlier closes stand: every reference file carries inputs from 1e7 to 1e12 beside its working grid; every property test is written to what doubles can give; every new message comes from the diagnostics-as-data path with a snapshot and an explained page. This is the largest release so far by count and the second hardest by engine work after 0.4.0: two new package crates, the first new estimator piece since 0.4.0 (demeaning), the checker's biggest growth (the schema pass) and the memory rules of section 6 of the Language Reference. Its weight falls on `zeff-columns`, `zeff-kernels`, `zeff-data`, `zeff-regress`, `zeff-ir` and `zeff-engine`.

2. **What `event()` computes and how its terms are named.** The catalogue row 252 gives `event(time, treat, ref: Int = -1)`, "event-study leads and lags inside a formula", after fixest's `i()`, and no section of either volume says more. Recommendation: `treat` is the period in which the row's unit is first treated, in the type of `time` (Int, or Date, both in the time variable's own unit), `NA` for a unit that is never treated; the relative period is `time − treat`; the term expands to one indicator column per relative period present in the data, except `ref:` (the period before treatment by default), each 1 in the rows of that relative period and 0 elsewhere; a never-treated row is 0 in every column, so such units are the controls, as fixest's `ref = c(-1, -1000)` arranges; the term names follow the category convention of section 7.2, `event=-3`, `event=0`, `event=2`, so `m.coef("event=0")`, `report` and `coef_plot` (0.7.0) read them like levels; `ref:` absent from the data is an error listing the periods present; `event` is refused outside a formula, as `interact` is. Needed at step 19. **Decided 1 November 2026: as recommended.**

- `format`'s `digits:` means decimals after the point, as `round(x, digits:)` and `report(digits:)` mean it, rounded half to even as the display rules round; without `digits:` a number prints as section 3.8 prints it; `big_mark:` inserts the separator every three digits of the whole part; `pattern:` takes the directives of the dates kernel (`%Y %y %m %b %B %d %H %M %S %%`) extended by the English weekday names `%a` and `%A` and the day of the year `%j`; `pattern:` on a number and `digits:` on a date are Z0401, and `digits:` with `pattern:` is Z0410.
- `save` writes CSV and TSV at this release under the writing rules of section 3.8 (UTF-8, no byte-order mark unless `bom: true`, LF, fields quoted only when needed, `NA` empty, dates ISO, categories as labels unless `codes: true`, Floats as the shortest text that reads back); Parquet, Arrow, Stata, Excel and JSON arrive with the reader interface of 0.11.0 and are refused with Z0716 naming the release, by the ruling of 0.1.0 that only working options are registered; a path outside `output/` but inside the project is allowed, a data root or an outside path is Z0707 (built); the written bytes are part of the four-target identity check, as the testing handbook requires of every file `save` writes.
- `append` matches columns by name: a column present in one frame only is filled with `NA` and named in a note, Int and Float join to Float, a category's levels are the union in first-seen order, any other type mismatch is an error (provisional Z06xx code), the left rows come first, metadata is kept where the left frame has it, and a panel declaration survives when both frames carry the same one.
- `distinct(vars)` keeps every column and the first occurrence in the current order, the whole frame being `[first..last]` as `drop_missing` names it; `duplicates(vars)` counts by identity (section 3.7: `NA` identical to `NA`); `merge` keys never match on `NA` (section 4.1) and `relation:` absent allows any relation but many-to-many (Z0603).
- `to_long` keeps the columns that are neither `id:` nor stub columns as they are, repeated per new row, as tidyr does; the stub columns must share a type (Int with Float joining; otherwise a provisional Z06xx error naming them); `names_type: Int` or `Date` that cannot parse a name is the same error. `to_wide` refuses two rows with one `(id, names_from)` pair (provisional Z06xx) and fills an absent combination with `NA`; its columns are "checked at run time" by the schema pass (step 21).
- `aggregate` takes definitions whose value is one scalar per group (reducers and arithmetic over them, `sd(lwage) / sqrt(n())`), refuses a column-valued definition with a message naming it (provisional Z02xx or the existing Z0401 as the checker allows), returns a `Frame` as catalogue row 119 says (the `by:` keys first, in key order with `NA` last, then the definitions in order), keeps the metadata of its `by:` columns only (section 4.3) and drops a panel declaration with a note (section 6); without `by:` it gives one row.
- `panel(unit:, time:)` writes the declaration into the frame's metadata store (`zeff.panel`, the key the Parquet profile names), which the IPC round trip already carries; `time:` is Int or Date (a `Period` is 1.x); a unit with two rows at one time, or `NA` in either variable, is refused (provisional Z06xx, with Stata's "repeated time values within panel" in its page); the index (rows sorted by unit then time, kept beside the frame) is built once at the declaration and reused by `lag`, `lead`, `diff`, `fill_forward`, `by:` on the unit and `fe:` on the unit (the "panel indexes" row of section 8.3, point 10); `describe` prints `panel worker × year` in its header (section 10.2); the declaration survives `where`, `sort`, `sample`, `add`, `update`, `select` and `drop` that keep both columns, `rename` of either column (renamed with it), `merge` on other keys and `distinct`, and is dropped with a note by `aggregate`, `to_wide` and a verb that drops or replaces either column.
- The panel functions inside `add` and `update`: `lag`, `lead` and `diff` need a panel declaration (a frame without one is an error naming `panel`, provisional Z06xx); a gap is one missing consecutive integer for an Int time and one missing calendar day for a Date (section 6, "Panels"), and `lag(x, 2)` looks two periods back, not two rows; `fill_forward` follows the panel's units, or `by:` groups, or the frame's row order when it has neither, as tidyr's `fill` does; `running_sum` and `running_product` follow the current row order within `by:` groups or over the frame (an `NA` makes the rest `NA`, as R), `running_sum` on Int stays Int with Z0211 on overflow (section 3.7); `rank` gives `NA` for `NA` (R's `na.last = "keep"`), Float under `ties: average` and Int otherwise; `bin` returns an ordered category whose levels are the intervals in order, labelled as R's `cut` labels them unless `labels:` is given, a value outside every interval becoming `NA` with a warning giving the count (provisional W02xx), the breaks sorted and `-Inf` and `Inf` as open ends.
- `sample` draws from the run's random stream keyed by its statement, as `draw` does; `seed:` given starts a stream of its own from that seed (the shared argument of section 6, "one is chosen and recorded when omitted"); without replacement the kept rows are chosen by a partial Fisher–Yates over the row positions, with replacement by `n` draws, the algorithm fixed and named on the page; `n:` and `frac:` together are Z0410; the kept rows come back in their original order as a selection, so the panel declaration and every column's metadata survive.
- Selection vectors (section 6, "Memory"): `where`, `sort` and `sample` record the row positions and share the parent's columns; a column is gathered into a compact buffer the first time a later step reads it; every remaining column is gathered and the parent released when the kept rows are fewer than half of the parent's or when the parent's binding is shadowed or has had its last use (`zeff run` frees a binding after its last use in the script, found by one pass over the IR; a session keeps bindings until shadowed); a model, `save` and the IPC writer always work on compact columns; a frame's reported size includes the parent buffers it keeps alive. Nothing a script prints changes: every verb's output, the identity series and the benchmark digests are unchanged, and a property test compares the selection form with the eager form bit for bit.
- Fused column expressions (open decision #49, option B, decided 23 October 2026): at step 22 an expression over columns in `add`, `update`, `where` and `aggregate` is compiled from the typed IR into one pass over the rows in fixed blocks, its reductions (`mean(lwage)` inside `add`) computed first in the kernel's fixed shape; no operation changes its order within a row and no reduction changes its shape, so the result is the same bits as the tree-walking evaluation, which stays in the engine as the oracle of the property test; the warning counts of each operation are kept as before.
- `fe:` in `reg`, by section 7.2 ("Fixed effects", "Collinearity", "Rows") and the reg page of the help examples: `fe:` takes `Terms` with `+` and `:` only (`*` is an error with help); rows with `NA` in a fixed effect are dropped and counted, then singletons, repeatedly until none remains, and counted; the outcome and the regressors (and the weights' square roots under `weights:`, the projections weighted) are demeaned by alternating projections with acceleration in the fixed order of the terms as written, to a tolerance of 1e-8 recorded in the run, in a scratch buffer of n × (k + 1) values, the rows ordered once by the largest fixed effect (free when it is the panel unit); the intercept is absorbed, every category gets K − 1 indicators and `- 1` has no effect; a regressor whose remaining norm is below 1e-8 of its original is "absorbed by fe:" and named in a note, pivoted QR runs on what remains, and W1004 warns of a regressor that keeps less than one per cent of its norm; the degrees of freedom count the absorbed effects' levels, less one for each effect after the first, except the effects nested within the cluster variable, which reproduces reghdfe and fixest's defaults (the reg page: "clustered degrees of freedom follow reghdfe"); R² within is the R² of the demeaned regression and R² overall is 1 − RSS/TSS of the outcome with the fixed effects' fit included, as fixest's `wr2` and `r2`; the printed header is section 10.2's (`fe: industry + year`, `fixed effects: industry (12), year (12)`, `no singletons` or their count); `report` gains the `Fixed effects` row and `r_squared_within` among its `stats:`; the self-check "converged demeaning" of section 11.1 runs after every fit; group indexes and demeaned columns are cached within a run under (fixed effects, rows used) beside the reused model matrices of 0.4.0, so a robustness table demeans once.
- The demeaning kernel is tested as `zeff-kernels` is: against the exact projection (the model matrix with explicit indicators, solved by the existing QR, within 1e-10 on the estimates and bit for bit on the four targets), with the weekly mutation job extended to it, and the kernel's corrected mean of the known-issues list (values that cancel, found at 0.5.0, step 17) reviewed at this step as that entry promised, its outcome recorded.
- The schema pass (section 11, "Checking before running"): the schema of every imported file is read from its header and the types guessed from its first 1,000 rows (a Parquet or Stata file's metadata when those readers arrive), cached in `.zeff/schemas/` keyed by the path with the file's size, modification time and BLAKE3 hash, refreshed when size or time changes, and applied with the import's own options (`types:`, `header:`, `names: snake`, `skip:`, `na_values:` for the dates note); the checker then carries each frame's columns through every verb that produces known columns and checks `Var`, `Vars`, `Terms` and `Formula` arguments, and a project function's `Var` parameters at the call, with the codes of section 3.7 before anything runs; `to_wide` and an `import` of a file that does not exist are "checked at run time", and after a run the columns they produced are cached under the statement's IR hash and used by later checks as warnings marked "from last run"; `--format json` carries both marks for the language server of 0.7.0; `zeff check` reports every error and `zeff run` stops at the first, as the text says; a data root's file keeps its last hash in the same cache, and a run whose file differs from it warns (provisional W07xx), which is section 2's "warns when a file has changed since the last run" until the run record of 0.11.0 carries it.
