# Z0708 — a file could not be fetched over the network

## Meaning
Zeff asked a server for a file and did not get it: there was no connection, the server answered with a status other than success, or the answer stopped before its end. The message names the address and what the server said. In this release the launcher is what fetches: the engine index, the key list, and the archive of an engine with its checksums and signature. What is fetched is trusted for its signature and never for the server it came from, so a failed request leaves nothing half done: the engine store is as it was.

## Common causes
- No network, or a network that needs a proxy: `HTTPS_PROXY` is honoured, and `[network] proxy` in `config.toml` names one.
- A mirror set by `ZEFF_MIRROR` or by `[network] mirror` that does not hold the file asked for.
- A server that is down for a while, or a download cut by a poor connection.
- A version before 1.0, whose engines are not on the public host yet: they come from a mirror or from an archive on the machine.

## Example
```
> zeff engine install 0.9.1
error[Z0708]: the engine index could not be fetched from `https://mirror.univ.example/zeff/engines/index.toml`: the server answered 500
  = help: the launcher fetches from the mirror `https://mirror.univ.example/zeff/`, set by `ZEFF_MIRROR` or by `[network] mirror` of `config.toml`; `zeff engine install --from <file>` installs an archive that is already on this machine
```

## Fix
Try again when the network is there, or name a mirror that holds the file. Without a network at all, bring the archive, `SHA256SUMS` and `SHA256SUMS.minisig` on a disk and install with `zeff engine install --from <file>`; with `--frozen` or `--offline` Zeff makes no request and says so (Z0710) instead of trying.
