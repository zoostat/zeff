# Z0417 — a definition derive cannot differentiate, or an effect margins cannot take

## Meaning
`derive` evaluates each definition at the estimates and differentiates it over the coefficients for the delta-method standard error. It differentiates `+`, `-`, `*`, `/`, `^`, `log`, `exp`, `sqrt`, `log1p`, `expm1`, `log10`, `log2` and `abs`; anything else in a definition, a comparison, a function of two arguments, a rounding, text, has no derivative here.

`margins` raises the same code for a variable whose effect it cannot compute: one that enters the model both as a number and as a category, so that neither a slope nor a difference between levels is its effect, or one whose slope is not finite in some row the fit used, as the slope of `sqrt(x)` is where `x` is 0. It raises it too for what cannot be held: a variable of `at:` or of `type: mem` that enters the model both ways, and a term that has no value at the values asked for, as `log(x)` has none with `x` held at 0.

## Common causes
- A comparison or a logical operator in a definition.
- A function that is not smooth, such as `round`, or one of two arguments.
- In `margins`: a variable written twice in the formula, once as it stands and once inside `category(...)`; a square root or a logarithm of a variable that is 0 in some row.

## Example
```
> m.derive(r = round(educ / exper))
error[Z0417]: `round(educ / exper)` cannot be differentiated: `round` cannot be differentiated
  = help: `derive` differentiates `+`, `-`, `*`, `/`, `^`, `log`, `exp`, `sqrt`, `log1p`, `expm1`, `log10`, `log2` and `abs` over the terms
```

## Fix
Write the quantity with the arithmetic and functions listed; round the printed result afterwards if needed. For `margins`, keep a variable either a number or a category in the model, and move a variable away from the point where its term has no slope (`sqrt(x + 1)`).
