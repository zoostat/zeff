# Z0603 — a merge whose keys do not relate as stated

## Meaning
`merge` joins two frames on key variables. When a key value repeats on both sides, every left row with it pairs with every right row with it, and the rows multiply: a many-to-many merge, nearly always a mistake, which `merge` refuses whether or not `relation:` was given. When `relation:` was given and the data do not have it, `one_to_one` with a repeated key on either side, `many_to_one` with one on the right, `one_to_many` with one on the left, the merge is refused with the count of repeated keys.

## Common causes
- A lookup frame with a duplicated row, so the key repeats on the right.
- A panel merged on the unit alone, when the key should be the unit and the time.
- The frames the wrong way round for the relation stated.

## Example
```
> let sales = frame(firm = [1, 1, 2], revenue = [8, 9, 11])
> let names = frame(firm = [1, 1], name = ["Acme", "Acme Ltd"])
> sales.merge(names, on: firm)
error[Z0603]: many-to-many merge refused
 --> scripts/main.zeff:3:7
  |
3 | sales.merge(names, on: firm)
  |       ^^^^^ firm repeats in both frames (1 key on the left, 1 key on the right)
  |
  = help: find the repeated keys with `names.duplicates(firm)` and remove them, then state `relation: many_to_one`
```

## Fix
`duplicates(firm)` on the frame named lists the repeated keys; `distinct(firm)` keeps the first of each, or add the variable that tells the rows apart to `on:`. Then state the relation you expect, so that a later file with the same fault is refused too.
