# Z0106 — a loop variable with a column's name

## Meaning
Inside a frame method a bare name is looked up in a fixed order (section 3.7, "Name lookup"): a loop variable or a function parameter in scope comes before the frame's columns. When the frame also has a column of that name, the two are a clash and the statement stops, rather than one of them winning in silence: `for y in vars(lwage, hours) { wages.reg(y ~ educ) }` must never regress a column called `y`.

## Common causes
- A loop variable named after a column: `for wage in vars(hours) { wages.mean(wage) }`.
- A short loop name, `x` or `y`, in a frame that has a column of that name.

## Example
```
> for wage in vars(hours) { print(wages.mean(wage)) }
error[Z0106]: `wage` is both the loop variable and a variable of wages
  = help: rename the loop variable, or the column with `rename`; inside a frame method a loop variable wins over a column, so a clash is never resolved silently
```

## Fix
Rename the loop variable, or rename the column with `rename` before the loop.
