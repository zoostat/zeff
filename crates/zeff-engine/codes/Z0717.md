# Z0717 — an engine's archive cannot be installed

## Meaning
An archive was given to the launcher and could not be installed for a reason other than its checksum or its signature, which are Z0711: the file is not named as an engine's archive is, it holds an engine for another kind of machine, one of the three files could not be read, or the archive was proved to be the publisher's and still could not be unpacked. An engine is unpacked into a folder of its own and moved into place only when every file is written, so the engine store is as it was: no engine is half installed.

## Common causes
- An archive renamed after it was downloaded: its name carries the version and the machine, and `SHA256SUMS` lists it by that name.
- The archive for another machine, such as the Linux one on a Mac.
- The archive alone, without `SHA256SUMS` and `SHA256SUMS.minisig` in the same folder.
- An engine store that cannot be written, or a disk that is full.
- A folder `engines/<version>` made by hand that holds no engine.

## Example
```
> zeff engine install --from zeff-0.9.1-linux-x86-64.tar.zst
error[Z0717]: `zeff-0.9.1-linux-x86-64.tar.zst` holds an engine for another kind of machine
  = help: this machine is macos-arm64; the archive for it is named with that word
```

## Fix
Do what the message's last line says: keep the archive's published name, take the archive for this machine, put the three files in one folder, or make room in the store. An archive that is proved and faulty as published is the publisher's fault, not yours: `zeff report-bug` writes a report.
