# Z0507 — `event` given a reference period the data lack

## Meaning
`event(time, treat, ref:)` leaves one relative period out as the base of the leads and lags, the period before treatment (−1) unless `ref:` names another, and the period named is not among the relative periods `time − treat` the treated rows take. Nothing can be fitted against a base no row is at, so the call stops; the message lists the periods present.

## Common causes
- A `ref:` written in calendar time (`ref: 2011`) where a relative period is meant (`ref: -1`).
- A panel whose treated units are all observed from the period of treatment on, so that −1 is never seen; `ref: 0` takes the period of treatment as the base.
- A Date time, whose relative periods are days: `ref: -1` is the day before treatment, and a panel observed weekly needs `ref: -7`.

## Example
```
> d.reg(y ~ event(year, treat, ref: 5), fe: unit + year)
error[Z0507]: `ref: 5` of `event(year, treat, ref: 5)` is not a relative period of the data
  = help: the relative periods present are -3, -2, -1, 0, 1, 2; `ref:` names the one left out as the base, −1 unless given
```

## Fix
Name a period the data hold, usually −1 or 0; the help lists them.
