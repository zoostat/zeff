# W0805 — iterate stopped at max: without converging

## Meaning
`iterate` called its `step:` function `max:` times (1,000 unless given) and `done:` never returned `true`. The loop stopped there, as section 5.5 promises every script finishes, and the state returned is the last one computed, not a converged one. The result may still be usable, but it is not what the stopping rule asked for.

## Common causes
- A `done:` rule that is too strict for the arithmetic: a tolerance below what doubles can give, or a comparison of a quantity that oscillates.
- A `step:` that does not contract: a fixed-point map that diverges or cycles for this start.
- A `max:` chosen for a fast algorithm and used with a slow one, such as EM near a flat likelihood.

## Example
```
> fn newton(s: Record, a: Float) -> Record { {x: (s.x + a / s.x) / 2} }
> fn close(old: Record, new: Record) -> Bool { abs(new.x - old.x) < 1e-12 }
> iterate(start: {x: 1.0}, step: newton, args: {a: 2.0}, done: close, max: 2)
x: 1.41667
warning: iterate stopped at max: 2 passes without done becoming true (line 3)
  = help: the state returned is the last one; raise `max:` or loosen `done:`, and `keep: true` shows the path
```

## Fix
Raise `max:` when the algorithm is just slow; loosen or repair `done:` when the tolerance cannot be met; look at the path with `keep: true` when the steps do not settle.
