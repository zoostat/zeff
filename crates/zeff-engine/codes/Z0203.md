# Z0203 — a condition that is not a Bool column, or an `if` on NA or a column

## Meaning
`where(condition)` takes an expression over the frame's variables that is a Bool for every row: `where(hours > 40)`. A single Bool (`where(true)`), a column of another type (`where(hours)`) or `NA` is not a condition over rows and is refused. Likewise `if` and `assert` (release 0.5.0) take one Bool, and a column or `NA` is an error, so that R's `if` versus `ifelse` confusion cannot arise.

## Common causes
- A variable written alone where a comparison was meant: `where(female)` is fine for a Bool variable, `where(hours)` is not.
- A comparison with `NA`: `where(x == NA)` is `NA` in every row; `is_missing(x)` is the test.
- A condition built from another frame's columns, or from a binding that is a single Bool.

## Example
```
> wages.where(hours)
error[Z0203]: `where` needs a condition that is true or false in every row, but this is a Column<Int>
```

## Fix
Write a comparison or a Bool variable: `where(hours > 40)`, `where(female)`, `where(is_missing(hours))`.
