# Z0711 — an engine's archive is not proved to be the publisher's

## Meaning
An engine arrives as an archive with two small files beside it: `SHA256SUMS`, which lists the checksum of every archive of a release, and `SHA256SUMS.minisig`, the publisher's signature of that list. The launcher first checks the signature against the key built into it, or against a key on its signed key list, and only then compares the archive's own checksum with the one listed. An archive that fails either check is not unpacked: not one file of it is written, and the engine store is as it was. The same code is raised for a key list that the built-in key did not sign, that does not read as a key list, or that is older than the list the store already holds.

## Common causes
- A download that stopped early, of the archive or of one of the two small files.
- A web page saved where the signature should be, when the address was wrong.
- An archive and a `SHA256SUMS` from two different releases.
- An archive from somewhere other than the publisher, or changed on the way.
- A launcher built from source before a key was published: it has no key and can prove nothing.

## Example
```
> zeff engine install --from zeff-0.9.1-linux-x86-64.tar.zst
error[Z0711]: `zeff-0.9.1-linux-x86-64.tar.zst` is not the file that was published: its SHA-256 is 4af923d007bfe9025c265805991727f91211c8b76ef01b3bb82e93d3376b21a2 and the published one is 174a2ea1628e97d6f30c1a42c7cb6b39b5d7d7bc7ba407477c0825a29e15d318; nothing was unpacked
  = help: a download that stopped early gives this, and so does a file changed on the way; fetch the archive again
```

## Fix
Fetch the archive, `SHA256SUMS` and `SHA256SUMS.minisig` again, all three from one release, into one folder, and install again. If the message says the signature is by a key the launcher does not trust, do not look for a way round it: the archive is not from the publisher of this launcher, and the check exists for exactly that case.
