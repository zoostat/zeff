# Z0610 — stub columns that to_long cannot turn into rows

## Meaning
`to_long(stub, ...)` gathers the columns whose names begin with the stub into one value column, and reads the rest of each name as `names_type:` says. It is refused when no column begins with the stub, when the stub columns do not share a type (Int joining Float), or when a name's rest does not parse as a whole number under `names_type: Int` or as a date under `names_type: Date`.

## Common causes
- A stub misspelt, or written without its separator: `"sales"` where the columns are `sales_2010`.
- One stub column read as text while the others are numbers.
- `names_type: Int` with a column such as `sales_total` among the years.

## Example
```
> let sales = frame(firm = [1, 2], sales_2010 = [120, 80], sales_total = [250, 160])
> sales.to_long("sales_", id: firm, names_to: "year", values_to: "sales", names_type: Int)
error[Z0610]: `sales_total` does not end in a whole number: `total` after `sales_`
 --> scripts/main.zeff:2:89
  |
2 | sales.to_long("sales_", id: firm, names_to: "year", values_to: "sales", names_type: Int)
  |                                                                                     ^^^ the type the names do not fit
  |
  = help: `names_type: Str` keeps the rest of each name as text; `rename` a column whose name is wrong
```

## Fix
`drop` or `rename` the column that does not belong to the series, convert the odd column with `to`, or read the names as text with `names_type: Str`.
