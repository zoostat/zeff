# Z0604 — both frames hold a column that is not a key

## Meaning
`merge` keeps the left frame's columns and adds the right frame's non-key columns. A non-key column present in both frames would give the result two columns of one name, so the merge is refused and the columns are listed. `suffixes: ["_l", "_r"]` keeps both, the first suffix on the left frame's column and the second on the right's; dropping one of them first keeps the other.

## Common causes
- Merging a frame with itself, or with a frame derived from it, so that every column is shared.
- A lookup frame that carries a column the data already have, such as `industry` on both a workers' and a firms' frame.
- Merging a second time with the same right frame, so that its columns are already there.

## Example
```
> let wages = dataset(wages).merge(dataset(firms), on: [firm, industry], relation: many_to_one)
note: merge: 18,412 rows matched; 0 left rows unmatched; 3 right rows unmatched (line 1)
> wages.merge(dataset(firms), on: firm)
error[Z0604]: columns `industry`, `size`, `founded` exist in both frames and are not a key
 --> scripts/main.zeff:2:13
  |
2 | wages.merge(dataset(firms), on: firm)
  |             ^^^^^^^^^^^^^^ shares a column with the left frame
  |
  = help: give suffixes: ["_l", "_r"] to keep both, or drop one of them first
```

## Fix
Add the shared column to `on:` when it is part of the key, give `suffixes:` when both versions are wanted, or `drop` the one that is not.
