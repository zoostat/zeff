# Z0226 — a comparison with the literal NA

## Meaning
`x == NA` and `x != NA` are written with the literal `NA` on one side. `NA` stands for a value that is not known, so a comparison with it is `NA` whatever `x` holds, never true and never false (section 4.1, "Missing values"): `where(score == NA)` would keep no row, and `if x == NA` would stop on a condition that is `NA`. The test the script means is `is_missing(x)`, and the checker refuses the comparison before anything runs.

## Common causes
- A habit from spreadsheets or SQL, where a missing cell is found by comparing.
- `where(x != NA)` written to keep the rows that have a value; `drop_missing` and `where(!is_missing(x))` do that.
- A `case` arm `x == NA => ...` meant to catch the missing rows.

## Example
```
> let s = frame(score = [72.5, NA, 60])
> s.where(score == NA)
error[Z0226]: `== NA` is never true: a comparison with `NA` gives `NA`, not true or false
  = help: write `is_missing(score)`; `NA` stands for a value that is not known, so nothing is known to equal it
```

## Fix
Write `is_missing(x)` for `x == NA` and `!is_missing(x)` for `x != NA`. A value that turns out to be `NA` when the script runs, a binding or a variable of a frame, still compares as section 4.1 says and gives `NA`; only the literal is refused.
