# W0703 — a value read from the clock

## Meaning
`today()` or `now()` was called, so the script's result depends on when it ran. The value is noted beside the call; `zeff run --replay` reuses the noted value once run records arrive (release 0.11.0), and a statement that depends on it is never served from the result cache. Nothing is wrong with the script.

## Common causes
- A date stamp in an output name or a table title.
- An age or a duration counted up to the day the script runs: `days_between(signed, today())`.

## Example
```
> today()
2026-11-01
note: today() read the clock: 2026-11-01 (line 1)
  = help: the value depends on when the script runs; `zeff run --replay` will reuse it (release 0.11.0)
```

## Fix
None needed. For a result that must not move with the clock, write the date: `date("2026-11-01")`. `zeff run --deny-warnings` refuses every use that no pragma allows; `// zeff: allow(W0703) reason` on the statement keeps one deliberately.
